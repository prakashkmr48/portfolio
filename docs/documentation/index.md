## Documentation Workflow

<div class="workflow-strip" markdown>

- :material-account-search-outline: **Audience**
  Define the reader, role, task, and technical depth.

- :material-file-tree-outline: **Structure**
  Map content types, navigation, headings, related pages, and reuse patterns.

- :material-pencil-outline: **Draft**
  Write Markdown with steps, examples, notes, warnings, and validation points.

- :material-check-decagram-outline: **Review**
  Validate with SMEs, product context, terminology, and technical accuracy.

- :material-cloud-upload-outline: **Publish**
  Prepare content for MkDocs, Sphinx, Confluence, GitHub, or product documentation portals.

</div>

## Sample Documentation Types

<div class="sample-doc-grid" markdown>

- **Concept topics**  
  Explain what a feature, API, system, or workflow does and why it matters.

- **Task topics**  
  Provide step-by-step instructions with prerequisites, expected results, and validation.

- **Reference topics**  
  Document parameters, fields, endpoints, error codes, configuration values, and commands.

- **Troubleshooting topics**  
  Help readers diagnose symptoms, understand causes, and apply resolutions.

- **Release communication**  
  Explain changes, enhancements, fixes, compatibility notes, and user impact.

- **Knowledge base articles**  
  Capture recurring questions, SOPs, support workflows, and self-service solutions.

</div>
