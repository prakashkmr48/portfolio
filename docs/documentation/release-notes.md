# Release Notes

Release notes explain what changed, why it matters, and what users may need to do next. I write release documentation that is clear for customers, support teams, product teams, and technical stakeholders.

## Release Notes Scope

<div class="content-grid" markdown>

- **New features**  
  User-facing descriptions, value, behavior, and related documentation links.

- **Enhancements**  
  Improvements to existing workflows, performance, usability, or configuration.

- **Fixes**  
  Resolved issues written in a clear, support-friendly way.

- **Known issues**  
  Current limitations, workarounds, and affected scenarios.

</div>

## Release Note Pattern

| Section | Purpose |
| --- | --- |
| Summary | High-level release overview |
| What's new | New functionality and user value |
| Changed behavior | Updates that may affect existing workflows |
| Fixed issues | Resolved defects or product issues |
| Known issues | Open issues and workarounds |
| Upgrade notes | Required actions, compatibility, or migration notes |
| Related documentation | Links to guides, API docs, or troubleshooting |
