# API Documentation

I create API documentation that helps developers understand how an API behaves, how to authenticate, how to send valid requests, how to interpret responses, and how to recover from errors.

## Scope

<div class="content-grid" markdown>

- **REST API references**  
  Endpoint purpose, methods, URLs, parameters, request bodies, responses, and status codes.

- **Authentication guides**  
  Token usage, credentials, permissions, authorization behavior, and security notes.

- **OpenAPI and Swagger**  
  Specification-driven API references, schema descriptions, examples, and review-ready API content.

- **Postman workflows**  
  Collection usage, environment setup, request examples, and API exploration steps.

</div>

## API Page Pattern

| Section | Purpose |
| --- | --- |
| Overview | Explain what the API or endpoint does |
| Prerequisites | Define access, credentials, environment, and required tools |
| Authentication | Describe tokens, headers, permissions, and security behavior |
| Request | Document method, path, headers, parameters, body, and examples |
| Response | Explain successful responses, schemas, examples, and field meanings |
| Errors | List status codes, causes, resolution steps, and retry guidance |
| Related topics | Link setup, configuration, troubleshooting, and developer guides |

## Sample Endpoint Structure

```yaml
endpoint_page:
  title: Create resource
  method: POST
  path: /api/v1/resources
  audience: Developers and integration teams
  includes:
    - Authentication requirements
    - Request headers
    - Request body fields
    - Successful response example
    - Error responses
    - Troubleshooting notes
```
