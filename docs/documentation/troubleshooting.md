# Troubleshooting Guides

Troubleshooting documentation is written for readers who need fast, accurate recovery. I structure troubleshooting content around symptoms, likely causes, clear resolution steps, validation, and escalation guidance.

## Troubleshooting Structure

<div class="content-grid" markdown>

- **Symptoms**  
  What the user sees, including messages, failed states, or unexpected behavior.

- **Causes**  
  Likely reasons the issue occurs, written in plain technical language.

- **Resolution**  
  Ordered steps that help the user recover or narrow the issue.

- **Validation**  
  How to confirm the issue is resolved.

</div>

## Article Pattern

| Section | Purpose |
| --- | --- |
| Issue | Short description of the problem |
| Applies to | Product, environment, version, or user role |
| Symptoms | Observable behavior |
| Cause | Known or likely causes |
| Resolution | Step-by-step fix |
| Verify | Checks after applying the fix |
| Escalate | What to collect before contacting support |
